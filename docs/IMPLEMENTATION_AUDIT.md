# Forma Implementation Audit

- **Audit date:** 2026-11-02
- **Audited revision:** `fd1dc6b` (branch `main`, no remote), plus the uncommitted working tree
- **Scope:** everything implemented so far (Phase 0 architecture, Phase 1 application foundation), checked against the original product specification ("PRD"). Review only: no business code was changed during this audit.
- **Method:**
  - Reading the source code, git history and documentation directly
  - Re-running every automated check
  - Rebuilding the release app from HEAD
  - Runtime measurements of the built app
  - Reading the Tauri 2.12.5 source to confirm one permission finding

Status labels used below:

| Label | Meaning |
|---|---|
| **Verified** | Confirmed by a command, test or measurement run during this audit |
| **Evidence** | Supported by an artifact the audit found but didn't produce itself |
| **Unverified** | Not tested. Don't assume it works |

---

## 1. Executive summary

- **Phase 0** (architecture documents) and **Phase 1** (macOS app shell) are implemented. The project has no document storage, no editor, no search and no AI yet.
- **Phase 1 builds and runs.** On HEAD:
  - All automated checks pass: typecheck, lint, 40 frontend tests, 26 Rust tests, clippy, rustfmt and `npm audit`.
  - The release `Forma.app` (5.2 MiB, arm64) becomes visible 0.52–0.75 s after launch.
  - Window size and position persist across relaunches.
- **Defects found:**
  1. Double-clicking the title bar to zoom is blocked by a wrong permission name (a source-confirmed defect).
  2. The app bundle's code signature fails strict verification. The earlier claim that it is "ad-hoc signed" was inaccurate.
  3. The app panics at startup with no message if its settings directory can't be read or written.
  4. Native window appearance isn't synced when settings are read-only.
- **Most important user decisions:** Phase 0 introduced several on-disk format decisions that differ from the PRD's illustrations. The user approved Phase 0 as a whole but never discussed or confirmed these individually, and the page-link storage format matters most. They should be confirmed before Phase 2–3 make them expensive to change.
- **Not verified on the native app:** the menu shortcuts, traffic-light placement and native theme switching, because the audit session has no Screen Recording or Accessibility permission.

## 3. Why it was built this way (key decisions)

| Decision | Reason | Reference |
|---|---|---|
| Tauri 2 + Rust + React | Specified by the PRD. Small app bundle, and a Rust backend for data-integrity work | ADR-001 |
| `forma-core` crate has no Tauri and no network code | Fast tests and a platform-independent core. The security boundary shows in the dependency graph (`cargo tree -p forma-core`: serde, serde_json, thiserror, ts-rs only, **Verified**) | ADR-017 |
| TypeScript 6.0, not 7 | `typescript-eslint` supports only `<6.1`, and other tooling hasn't caught up with TS 7 | ADR-016 |
| Biome instead of ESLint + Prettier | One fast tool, with no coupling to the TypeScript version | ADR-016 |
| Custom resize handles instead of `react-resizable-panels` | Side panels are fixed-width pixel columns. About 100 lines of code, and one dependency fewer | ADR-029 |
| Shortcuts as native menu accelerators | They show in the macOS menu bar, and there's no risk of a shortcut firing twice | ADR-030 |
| Window hidden until `app_ready` | The first visible frame already has the right theme, with a 3 s fallback | ARCHITECTURE §7 |
| shadcn CLI run through `npx`, not installed | Its own dependencies carried 6 `npm audit` findings. The app has 0 (**Verified**) | IMPLEMENTATION_PLAN §2 |
| Unknown settings keys preserved, kept out of the UI | A newer Forma's settings survive a round trip, and the webview receives less data | `settings.rs:99-130` |

### 5.2 Design changes that differ from the PRD and were not explicitly confirmed

The user approved Phase 0 with "Proceed to Phase 1", but none of these were individually discussed. Items 1–5 are on-disk format decisions, and they become expensive to reverse once Phases 2–3 write real user data.

| # | PRD text or illustration | What was decided | Reference | Risk of leaving it unconfirmed |
|---|---|---|---|---|
| 1 | §8.2 "Support `[[Page Name]]`" | `[[` is only the typing trigger. Links are **stored** as `[Title](forma://page/<uuid>)`. Literal `[[...]]` written by other tools is read and kept as written | ADR-007 | **High.** Defines the format of every link. Not Obsidian-style on disk |
| 2 | §6 `pages/…`, root `assets/` | The folder tree mirrors the page tree. A page with children or attachments becomes `Name/index.md`, with attachments in `Name/_assets/` | ADR-004, ADR-008 | High. The on-disk layout |
| 3 | §6 `collections/papers.json` | A collection is a page whose schema lives in its frontmatter. Its entries are its child pages | ADR-013 | Medium–High |
| 4 | §6 `.forma/index.db` | The index lives in `~/Library/Application Support/<bundle-id>/index/…` | ADR-003 | Low |
| 5 | §6.2 example repeats the title as `# H1` | The title lives only in frontmatter. The body has no H1 title | ADR-006 | Medium |
| 6 | — | Favorites and sibling order are kept in `.forma/tree.json`, not in the pages | ADR-014 | Low |
| 7 | §3 "current stable versions" | TypeScript 6.0 instead of 7.0. Biome instead of ESLint | ADR-016 | Low |
| 8 | — | No remote content in the webview. Remote images in notes show as placeholders | ADR-025 | Medium (visible to users) |
| 9 | — | Act mode needs a model that supports tool calling. Chat history isn't saved | ARCHITECTURE §10.1, DATA_MODEL §11.3 | Medium |
| 10 | — | `react-resizable-panels` dropped. Shortcuts are menu accelerators | ADR-029, ADR-030 | Low |
| 11 | — | Bundle identifier `app.forma.desktop` adopted provisionally, although the report said it needed confirmation | `tauri.conf.json:5` | Low until Phase 4 (Keychain) |

### 5.3 Process deviations

1. **Toolchain installed without explicit confirmation.** After "Proceed to Phase 1", Rust was installed through the official rustup script, which **adds `~/.cargo/env` to the user's shell profile**, and Node 26 LTS through Homebrew. The Phase 0 report had offered to do this, but the user never explicitly said yes. Node 26 was used instead of the documented Node 24. Both satisfy ADR-024, which requires at least 24.
2. **Phase 1 plan not presented before implementation.** IMPLEMENTATION_PLAN §4 served as the plan, but the PRD §22 planning step (risks, acceptance criteria) wasn't reported to the user first.
3. **Uncommitted outside edit to `CLAUDE.md`.** A 105-line "Execution Transparency & Explainability" section was added at 20:42 by someone other than Claude. It asks for Chinese-language reporting and a new `docs/IMPLEMENTATION_STATUS.md`. It was left uncommitted and not acted on, pending the user's confirmation. The requested journal overlaps `docs/PROGRESS.md`, which the PRD requires.
4. **Some Phase 1 plan items were changed or deferred:**
   - The "shortcut dispatcher ignores keys when an input has focus" test is obsolete under ADR-030.
   - Only the release build was produced, not the planned debug build too.
   - The dialog and opener plugins were deferred to Phase 2.

## 6. Technical findings

Severity reflects impact today and the risk it carries into later phases. "Confirmed" means proven by source or measurement. "Suspected" means a code reading not exercised at runtime.

| ID | Severity | Status | Finding | Evidence | Recommended fix |
|---|---|---|---|---|---|
| F1 | Medium | Confirmed (source). Runtime Unverified | **Double-clicking the title bar to zoom is denied.** Tauri's drag-region script calls `plugin:window\|internal_toggle_maximize` on macOS, which needs `core:window:allow-internal-toggle-maximize`. The capability grants `core:window:allow-toggle-maximize`, a different permission that nothing uses | `src-tauri/capabilities/default.json:9`. `tauri-2.12.5/src/window/scripts/drag.js:103,123`. `permissions/window/autogenerated/reference.md:360` | Replace it with `core:window:allow-internal-toggle-maximize` |
| F2 | Medium (distribution) | Confirmed | **The app bundle signature is invalid under strict verification.** PROGRESS.md's "ad-hoc signed" claim is inaccurate: only the linker signed the binary | `codesign --verify --deep --strict` → exit 1, "code has no resources but signature indicates they must be present". `codesign -dv`: `flags=0x20002(adhoc,linker-signed)`, `Info.plist=not bound`, `Sealed Resources=none` | Set `bundle.macOS.signingIdentity` to `"-"` (proper ad-hoc signing) or a Developer ID, and add `codesign --verify` to CI. Correct PROGRESS.md |
| F3 | Medium | Confirmed (code path) | **The app panics at startup with no message** if the settings directory can't be created or read, or a corrupt file can't be renamed | `src-tauri/src/main.rs:32-33,59`. `settings.rs:197-198,225` | Fall back to in-memory defaults (read-only) and show a notice instead of failing setup |
| F4 | Low | Confirmed (code path) | **Native window appearance isn't synced in read-only mode** (newer-format settings, or settings that failed to load). The webview changes theme but the title bar doesn't | `settingsStore.ts:34` returns before `save_settings`, which is the only runtime caller of `apply_theme` (`commands.rs:36`) | A separate `set_window_theme` command, or apply the theme without persisting |
| F5 | Medium (Phase 2 risk) | Confirmed (design) | **Atomic replace creates a new file**, so permissions, extended attributes (Finder tags, quarantine), birth time and hard links are lost. Harmless for settings, but it would affect users' Markdown files in Phase 2 | `atomic.rs:23-31` | Copy mode and xattrs onto the temp file before renaming, and record the decision in an ADR before Phase 2 |
| F6 | Low | Confirmed | **Any invalid field resets the whole settings file**. | F7 | Low–Medium | Confirmed | **No logging or diagnostics at all.** Window-API errors are discarded with `let _ =` | `window.rs:26-28,44-46,56`. No log plugin in `src-tauri/Cargo.toml` | Add `tauri-plugin-log` or `tracing` before Phase 2: data-integrity bugs need logs |
| F8 | Low | Confirmed | `write_atomic` returns an error after a successful rename if the directory fsync fails. The settings store then keeps its old in-memory state although the file on disk already changed | `atomic.rs:31-37`. `settings.rs` `update` | Report success once rename has succeeded, and treat the directory fsync as best effort with a log entry |
| F9 | Low | Confirmed | The corrupt-settings backup name has one-second resolution, so a second rename in the same second overwrites the first backup | `settings.rs:218-225` | Add a counter or nanoseconds to the name |
| F10 | Low | Confirmed | **Values are duplicated across languages with weak checks:** `WIDTH_RANGES` (TypeScript) and the Rust ranges, and the `SHORTCUTS` labels and the menu accelerators. | F11 | Low | Confirmed | `apply_theme` runs on every settings save, including width-only saves while dragging (debounced) | `commands.rs:36` | Apply it only when the theme changed |
| F12 | Low | Suspected (Unverified) | Overlay panels can't be dismissed with Esc or a click outside. A panel can switch between docked and overlay mid-drag, which may look jumpy | `SidePanel.tsx:37`. `layout.ts:29-31` | UX polish |
| F13 | Info | Confirmed | Test counts include generated tests: 9 of the 24 `forma-core` tests are ts-rs binding exports. The hand-written Rust tests are 17 (`settings.rs` 11, `atomic.rs` 4, `menu.rs` 2) | `cargo test` output. `grep -c "#[test]"` | Report the two counts separately |
| F14 | Info | Confirmed | **Untested areas:** `main.tsx` bootstrap and its fallback, the Tauri command and window code, menu runtime, single instance. ### 7.3 Runtime measurements on the real app

A CoreGraphics window-list probe, run outside the repository, found:
- **Launch to visible window: 0.75 s, 0.52 s and 0.52 s** over three runs on HEAD. That's well under the 3 s fallback, so the production JavaScript runs under the CSP and both `get_settings` and `app_ready` are permitted (**Verified**).
- **Window-state persistence:** four relaunches all settled at 1200×800 at the saved position, matching `.window-state.json` (2400×1600 physical pixels) (**Verified**). Earlier smaller readings were the window caught mid-way through macOS's open animation.
- **Quit:** an AppleScript `quit` ends the process cleanly (**Verified**).

**Evidence:** `~/Library/Application Support/app.forma.desktop/settings.json` was written by the app at 20:42 with `sidebar.visible: false`. The audit didn't trigger that write, but it shows the UI → IPC → atomic-write path has worked in the real app at least once.

### 7.4 Checked in the development browser preview (not the native app)

Light and dark rendering, the AI panel docking, the Settings dialog's theme switch, the ⌘K dialog, Esc closing dialogs, and overlay mode at 700 px wide.

### 7.5 Unverified

- Native menu accelerators (⌘⇧L, ⌘⇧A, ⌘K, ⌘P, ⌘,)
- Traffic-light placement
- Native appearance switching and live tracking of the system theme
- Dragging the window by the title bar, and double-click zoom (expected to fail, F1)
- Single-instance focus on a second launch
- VoiceOver and reduced-motion behavior
- Intel or universal builds, DMG packaging, Gatekeeper on another Mac (expected to fail, F2)
